## 一、租用实例

### 1. 计费方式
- **推荐「按量计费」**：随开随停，训练完关机就不扣 GPU 钱。
- ⚠️ **余额耗尽 = 强制关机**（数据盘保留，不是释放）。训练前务必确认余额够撑完全程。
- **传数据/装环境阶段可先用「无卡模式」开机**（¥0.1/h），比正常计费便宜；要正式训练时再切换成正常模式。

### 2. GPU 型号
- **推荐 RTX 5090 ×1**：性价比高，单卡足够大多数训练任务。
- GPU 数量一般 **1 张即可**，多卡会改变 batch 口径，非必要不加。

### 3. 镜像（最关键，配错开机即崩）
- **必须选：`PyTorch 2.8.0 / Python 3.12 (ubuntu22.04) / CUDA 12.8`**。
- 原因：RTX 50 系是 Blackwell 架构（sm_120），**必须 CUDA ≥ 12.8 且 PyTorch ≥ 2.7**。
  - 如果选 PyTorch 2.3.0 + CUDA 12.1 → 开机就报 `no kernel image is available for execution on the device`。
  - 对照：5090/5080 → torch ≥2.7+cu128；4090/4080 → ≥2.1+cu121 即可；3090/A100 → ≥1.13+cu118 即可。
- 系统盘 30 G + 数据盘 50 G：**小数据集够用，但只要上了影像/视频/点云这类数据，或者预处理会产生大量中间文件，50 G 很容易爆**。数据盘不够时按**第五章**扩容（很便宜，但按天扣、关机也扣）。系统盘只有 30 G 且会被重置系统/换镜像清空，**不要把数据放系统盘**。

### 4. 地区选择
- **优先选目标 GPU 型号机器多的地区**。
- 理由：万一你租的机器显卡被别人占用，可以**克隆实例到同地区别的机器**（本地区克隆非常快，跨地区很慢）。
- ⚠️ **克隆实例默认只克隆系统盘/镜像配置，数据盘内容不会自动跟着走**：可以在克隆实例时勾选“系统盘”，就会把所有东西都克隆过去。或者，克隆系统盘与镜像到新机器后，用平台提供的**「跨实例拷贝数据」**功能，把数据盘（如 `/root/autodl-tmp/<项目名>` ，或直接输入一个星号 * 全部转移）从旧实例拷到新实例。

## 二、提前让 AI 准备几个 sh 脚本

本 SKILL 同目录的 `scripts/` 文件夹里已备好这 4 类脚本的**通用模板**——生成具体脚本时，让 AI 先读模板，再把顶部「可配置区」和正文里标 `⚠ 按项目改` 的地方替换成项目实际值；无对应内容的段落删掉，没覆盖到的自行补充。

需要随项目一起打包上传的脚本如下：

| 脚本 | 作用 | 要点 |
|---|---|---|
| `scripts/run_all.sh` | 全流程一键跑 | 起正式训练；**断点续训逻辑由各 `trainer.py` 负责**（本脚本只按顺序调用）；日志重定向；自带**测试跳过判据**（判据 A 优先，别把"文件数"当"case 数"比） |
| `scripts/setup_env.sh` | 一键补环境 | **只补缺的包，绝不覆盖镜像自带 torch/numpy/scipy**；先检测再装 |
| `scripts/monitor.sh` | 随时查进度 | **在关掉原终端、另开新终端后也能用**；读日志/标志文件/checkpoint，输出已完成、进行中、剩余。⭐ **epoch 按编号去重、测试按 case 计数**（别数日志行数/文件数，口径见脚本配置区） |
| `scripts/pretest.sh` | 正式跑前预检 | 见下 |

### `pretest.sh` 要尽可能全面，包含两块

**① 自检**：数据、权重、依赖、训练→存权重→评测→续训整条链路。

**② 预估总时长**（用于设置定时关机）：
- **不要依赖模型自带预估功能**（很多模型只用 tqdm，没有现成接口）。
- ⭐ **计时试跑必须"全量规模"**：用**正式训练列表 + 正式 batch**跑 N 个 epoch（默认 3，`--timing-epochs N` 可调），再按每 epoch 实测耗时 × 正式 epoch 数折算。
  - ⚠️ **绝不能用微型列表计时**（如 `head -n 4` 只取几行）：那会让 1 个 epoch 只有几次迭代，而正式训练常有上百到几百次（差 70~90 倍很常见），折算出的总时长会**偏小一到两个数量级**，据此设定时关机会**提前掐断训练**。
  - 微型列表**只用于测试**跑通链路（测试每个 case 通常只要几十秒）。
- 让 **AI 根据项目实际情况自行编写计时与预估逻辑**，例如：
  - 从训练脚本**自己写出的日志**里取**相邻 epoch 的时间戳**算每 epoch 耗时（比墙钟更准，也不怕 tqdm 无 ETA）；
  - 计入验证、保存 checkpoint、评测等额外开销；
  - 全流程有多个模型或多轮训练时，分别预估后**累加**；
- 最终输出**总预估时长**，供你到实例页面设定时关机；短程外推，epoch 越多越准，设定时再加 10~20% 余量。
- 具体写法与骨架见 `scripts/pretest.sh`（含 `--dry-run` / `--no-smoke` / `--timing-epochs N` 参数和 `record_timing` 的日志解析逻辑）。

## 四、上传文件（本地 → 云服务器）

上传阶段不需要 GPU，可先用**无卡模式开机**（¥0.1/h）再传，省钱；传完、环境装好，要训练时再切回正常模式。

### 0. 先用对终端（必踩坑）
- **必须用 Git Bash / Cmder / WSL**。
- **PowerShell 管道会损坏二进制**：`tar cf - | ssh …` 在 PowerShell 里按文本逐行处理，数据途中就坏了且传完才炸。CMD 管道虽透明但**不展开通配符**。
- 自检：`uname -a` 看是否是 Git Bash 环境。

### 1. 先确认哪些文件需要传
- 看训练代码实际读取哪些文件/目录，**不需要的目录可以不传**，能显著减小体积。
- 代码里没有引用的原始数据、可视化素材、IDE 配置等，都可以排除。
- ⭐ **传之前先估体积**：本地 `du -sh <目录>` 看一眼总量。若接近或超过数据盘免费额度 50 GB（还要算上预处理产物），**先按第五章扩容再传**——tar 流没有断点续传，传到一半因空间不足失败要从头再来。

### 2. 打 tar 流上传（推荐）
在**项目目录**右键「Git Bash Here」，执行：

```bash
tar cf - --exclude='<不需要的目录1>' --exclude='<不需要的目录2>' . \
  | ssh -p <端口> root@<地址> \
    "mkdir -p /root/autodl-tmp/<项目名> && cd /root/autodl-tmp/<项目名> && tar xf -"
```

- **关于自动解压**：命令里的 `tar xf -` 就是在服务端接收数据流后**立即解压**，传完**不需要再手动解压**。
- **放置路径**：`/root/autodl-tmp`（数据盘）。官方明确「重置系统或更换镜像只清空系统盘，**数据盘不受影响**」。
- ⚠️ **tar 流无断点续传**：断了要从头。本地上行不稳就改用「先打单文件 tar + FileZilla SFTP」或官方公网网盘（AutoPanel，速度 5~20 MB/s，支持断点续传）。
- ⚠️ **tar 流看不到进度**：本地只能看到“还在传”。想在本机看可给 tar 加 `--checkpoint=1000 --checkpoint-action=dot`（点走 stderr，不污染数据流）。
- ✅ **云端盯体积（推荐，另开一个 JupyterLab 终端）**：tar 流落地目录是**一边解包一边长大**的，所以**上传还没开始就先把它开着**：
  ```bash
  watch -n 5 'du -sh /root/autodl-tmp/<项目名> 2>/dev/null; \
              find /root/autodl-tmp/<项目名> -type f 2>/dev/null | wc -l'
  # 容器里没 watch 就用：
  # while true; do clear; du -sh /root/autodl-tmp/<项目名>; \
  #   find /root/autodl-tmp/<项目名> -type f | wc -l; sleep 5; done
  ```
- **传完判据**：体积涨到与本地一致、文件数不再增加，**且本地那条 tar 命令退回提示符** ⇒ 传完了。最终仍以「文件数 / 体积与本地一致」为准（命令在 JupyterLab 终端跑）。

### 3. 备选上传方式
- **FileZilla SFTP**：拖拽上传，支持文件夹整体上传。
- **JupyterLab 网页上传**：⚠️ **不支持文件夹**，小文件多时极慢，不推荐。
- **官方公网网盘（AutoPanel）**：固定下载到 `/root/autodl-tmp`，支持断点续传，官方「强烈推荐」。

## 五、数据盘容量不足：扩容

数据盘免费额度 **50 GB**，挂载点是 `/root/autodl-tmp`。超出这个量就必须扩容，否则会直接失败。

### 1. 什么时候会撑爆
- **训练数据本身大**：医学影像、视频、点云、多数据集合并训练，几十到上百 GB 很常见。
- **预处理产物比原数据还大**：裁 patch、重采样、转 `.npy`/`.h5` 缓存、生成 mask/标注缓存，常常是原数据的 1~3 倍。
- **一开始就想上传很多文件**：⚠️ **不建议**（除非有包月/包年不限量套餐）。上传本身耗流量、耗时间，几 GB 以上的上行在本地是实打实的时间和带宽成本。正确做法是**先按第四章第 1 节把不需要的文件全排除**，再决定要不要扩容。
- 具体表现：`df -h` 显示接近 100%，或上传/预处理中途报 `No space left on device`（tar 流中断后**无断点续传、要从头再来**，很亏）。

### 2. 先量体积，再决定扩多少
在 JupyterLab 终端里：

```bash
df -h /root/autodl-tmp                              # 总量 / 已用 / 剩余
du -sh /root/autodl-tmp/* 2>/dev/null | sort -h     # 谁在占地方
du -sh /path/to/原始数据 /path/to/预处理输出          # 分类估体量
```

估算口径：`所需 ≈ 原始数据 + 预处理产物 + checkpoint/日志 + 结果 + 20~30% 余量`。

- **最好在上传之前就估好并扩完**：tar 流没有断点续传，传到一半因空间不足失败要从头再传一遍。
- 上传阶段是**平台页面操作**，无卡模式下也能扩，不用等切正常模式。

### 3. 怎么扩
控制台容器实例（<https://www.autodl.com/console/instance/list>）→ 找到该实例 → 更多 → 扩容数据盘→ 填扩容容量（会在免费的50GB基础上增加的容量） → 确认。**立即生效、按天计费**。

三个必须知道的约束：

- ⚠️ **可扩空间是"公用池"**：能扩到多大，取决于**那台宿主机当下还有多少空闲空间**，页面上能选的上限就是当前上限。如果只能扩到 80 GB 而你需要 150 GB，说明这台机器余量就这么多——这时要考虑克隆实例到别的机器（当数据盘的体积已经超过 50 GB时，需要在克隆之前先给目标机器扩容好，在选机器的阶段那个页面底部就能直接扩容）。
- ⚠️ **扩容后无论开不开机都在收费**：存储费按天走，和 GPU 按时计费是两套账。**“关机省钱”对扩容出来的这部分不成立**——关机只停 GPU 钱，扩容的存储费照扣。
- 可随时缩容，但缩容后的数据盘空间不能少于当前其已经被占用的空间。

### 4. 价格参考（很便宜，但按天累计）
- 平台报价：**50 GB → 150 GB（即 +100 GB）约 ¥0.67/天**，折合约 **¥0.0067/GB/天 ≈ ¥0.2/GB/月**。
- 对比 GPU（正常模式几元/小时），存储确实便宜；但它是**按天累计**的：+100 GB 跑一周 ≈ ¥4.7，跑一个月 ≈ ¥20。
- 结论：**训练期间该扩就扩，别为了省几块钱让训练中途失败**；训练一结束立刻按下面第 5 点降下来。

### 5. 训练结束后：清理 → 缩容 / 释放
扩容费是持续的，所以收尾时务必处理：

1. **清掉“可再生”的大文件**（优先，通常一次能腾出几十 GB）：
   - 预处理中间产物（patch 缓存、`.npy`/`.h5`、重采样副本）；
   - 上传时解压出来的重复副本、原始压缩包；
   - 冗余 checkpoint（比如只留 `best` / `last`，中间 epoch 的删掉）；
   - 调试用的可视化导出图、临时日志。
2. **删之前先确认**：`du -sh` 定位大头 → 逐个确认它“删了能靠代码重跑快速再生成”（比如需要重新训练才能得到的就不能快速再生成，不能删） → 再动手。**原始数据、最终权重、核心日志不要删。**
3. 删完 `df -h` 确认空间降下来了。
4. 再去实例页面**缩容**，或直接**释放实例**（仅当你确定这个实例确实没用了的时候）。不缩不释放，这笔钱就一直扣着。

> ⚠️ 顺带一条：**别把大数据塞进系统盘**去“绕过”扩容。系统盘只有 30 GB，更小，而且**重置系统 / 更换镜像会清空系统盘**，两头不讨好。

## 六、环境快检（上传后 10 秒确认镜像没配错）

```bash
nvidia-smi
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available(), torch.cuda.get_device_capability())"
```

- ⚠️ **`ssh host "命令"` 里没有 `python`**：非交互非登录 shell 不读 `/root/.bashrc`，conda PATH 没挂上。
  - ❌ `ssh -t` 无效（`bash -c` 即使 stdin 是 tty 也不进交互模式，仍不读 `.bashrc`）。
  - ✅ 正解：**走 JupyterLab 网页终端**（交互式、PATH 完整、不用密码、不怕本地断网）。
  - ✅ 备选：`ssh host 'source /root/.bashrc; <cmd>'` 或 `ssh host 'bash -lc "<cmd>"'` 或绝对路径 `/root/miniconda3/bin/python`。

- 装完可以跑一个最小导入测试确认没有报错。

## 九、启动正式训练（脱离终端运行）

```bash
cd /root/autodl-tmp/<项目名>
TS=$(date +%Y%m%d_%H%M%S)
nohup bash run_all.sh > "run_all_${TS}.log" 2>&1 &
echo $!
```

- `nohup … &` 让进程**脱离终端**，`> "run_all_${TS}.log" 2>&1` 把 stdout/stderr 都重定向到该次运行的独立日志（带时间戳，不覆盖历史）。
- **同命令重跑 = 断点续训**：已完成的自动跳过、训一半的从 checkpoint 接着来（前提是训练脚本本身支持）。

### ⭐ 关了什么会停、什么不会停
- ✅ **不影响训练**：关 JupyterLab 终端标签、关浏览器、本地关机断网。
- ❌ **会打断训练**：**实例本身关机 / 释放 / 重置系统**。
- 记住一句：**关浏览器 ≠ 关机**。

### 关于 `tmux` / `screen`
- 如果更喜欢交互式会话、随时 attach 回来看：
  ```bash
  tmux new -s train          # 新建会话
  python train.py            # 在会话里跑
  # Ctrl+B 然后按 D 分离；回来用 tmux attach -t train
  ```
- AutoDL 官方三选一：JupyterLab 终端 / `screen -U`（防中文乱码）/ `tmux`。**本质都是让进程脱离终端**，`nohup` 是最轻量的那一种。

### ⭐ 定时关机（避免白烧余额）
- **不要在不确定训练时长的情况下让它跑一整晚**：有可能睡过了，训练早就结束了，实例还在计费。
- **确定训练大概需要多久后，去实例页面设置定时关机**（实例页面就能设置，很方便）。
- 建议把定时关机时间设为 `pretest.sh` **输出的总预估时长 + 余量**（留出评测、保存结果的时间），既不会中途被杀，也不会空转太久。

## 十、查看训练进度

- 实时看日志：`tail -f "$(ls -1t run_all_*.log | head -1)"`（跟踪最新那次运行）
- 或直接用 `bash monitor.sh -w` 看面板。
- 具体输出目录和完成标志取决于训练脚本的设计；一般脚本会把每个配置/任务的日志写到独立目录，完成的会有标志文件，断点看 checkpoint。
- ⭐ **数 epoch 要"按编号去重"，不要数日志行数**：训练日志通常是**追加**的（不是每次重写），断点续训会把上次被打断的那一轮**重跑一遍** ⇒ 该 epoch 的日志行会出现两次，按行数计数就会显示"训完 151"（真实仍是 150，**训练与权重都没问题**，只是计数口径骗人）。正确做法：提取行里的 epoch 编号后去重，例如
  ```bash
  sed -nE 's/.*Train epoch: ([0-9]+).*/\1/p' log.txt | sort -n | uniq | wc -l
  ```
- ⭐ **数测试产物要"数 case"，不要数文件**：很多项目每个 case 会输出多份（预测 / 原图 / 金标准），数 `*.nii.gz` 会把 6 个 case 显示成"已测 18"。要用能唯一标识 case 的模式（如 `*_pred.nii.gz`），并与测试列表的行数对照。
- 监控资源：`nvidia-smi`

## 十二、收尾与省钱

- **结果拷回后「关机」而不是「释放」**：关机数据盘保留；⚠️ **连续关机 15 天实例会被释放**，数据清空。
- **善用无卡模式**：传数据、装环境、调试脚本时用无卡模式（¥0.1/h）开机；只有真正训练时才切正常模式。注意切模式需要先关机再开机，训练前记得确认 `nvidia-smi` 能看到卡。
- **余额是硬风险**：长时间训练前确认余额足够；余额耗尽会被强制关机（可续训，但要重新开机 + 重跑命令）。
- **善用定时关机**：关机时间 = `pretest.sh` 输出的总预估时长 + 余量，避免空转浪费。
- ⚠️ **扩容出来的数据盘不会因为关机而停止计费**：收尾时按**第五章第 5 点**清理可再生的大文件，再缩容或释放实例，否则这笔存储费会一直扣下去。

## 十三、让 AI 提供分阶段执行清单

当 AI 已按本 SKILL 备好项目文件与 4 个脚本（`run_all.sh` / `setup_env.sh` / `monitor.sh` / `pretest.sh`）后，**应主动问用户一句**：

> 需要我把从上传到拉回结果的各阶段命令整理成一份可直接复制粘贴的清单吗？如果要，请把 AutoDL 实例卡片上的 **SSH「登录指令」**那一行发我（形如 `ssh -p <端口> root@<地址>`）；**密码不用发**（登录/上传时你自己交互输入）。

用户同意并给出登录指令后，**按下面 8 个阶段生成命令清单**（用真实端口/地址/项目名/脚本名替换占位符）：

| 阶段 | 在哪里执行 | 做什么 |
|---|---|---|
| **阶段 1 · 上传** | 本地 Git Bash | 在项目目录打 tar 流上传到 `/root/autodl-tmp/<项目名>`（排除无需上传的目录；另开终端盯体积） |
| **阶段 2 · 登录 + GPU 预检** | 云端 JupyterLab 终端 | 开一个终端会话；`nvidia-smi` + torch/CUDA/算力打印，确认镜像与卡匹配 |
| **阶段 3 · 补依赖** | 云端 JupyterLab 终端（同一会话） | `bash setup_env.sh`（只补缺，不动镜像自带 torch/numpy/scipy） |
| **阶段 4 · 预检 + 拿总时长** | 云端 JupyterLab 终端（同一会话） | `bash pretest.sh`；跑完记下"总预估训练时间"，用于阶段 7 设定时关机 |
| **阶段 5 · 启动（脱离终端）** | 云端 JupyterLab 终端（同一会话） | `TS=$(date +%Y%m%d_%H%M%S); nohup bash run_all.sh > "run_all_${TS}.log" 2>&1 &`；随后可安全关闭该终端/浏览器 |
| **阶段 6 · 监控** | 云端 JupyterLab 终端（推荐新开一个；不新开也行） | `bash monitor.sh -w` 看进度面板；或 `tail -f "$(ls -1t run_all_*.log \| head -1)"` 跟踪最新日志 |
| **阶段 7 · 定时关机** | AutoDL 实例页面（网页） | 按阶段 4 的总预估时长 + 10~20% 余量，在实例页面设定时关机，避免空转烧余额 |
| **阶段 8 · 拉回结果** | 本地 Git Bash | 只拉需要的（模型权重、日志、图表）：`scp -rP <端口> root@<地址>:/root/autodl-tmp/<项目名>/<结果目录> .`。**实在不确定该拉哪些文件时**：先用 `ssh` 列体积/清单（`du -sh` / `find ... -printf '%s\t%p\n'`）判断哪些大而不需要；要更保险就用 **`tar` 干跑**——跟上传命令对称，只把最后的 `tar xf -` 换成 `tar tf -`，就只列文件不落地；确认后再换成 `tar xf - -C <本地目录>` 正式拉。**全程不需要 rsync**（本地默认没有，装起来也麻烦）。 |

**生成规则**：
- 每阶段给出**可直接复制粘贴**的整段命令（含 `cd`、含真实端口/地址）。
- ⭐ **阶段 1 之前先判容量**：先看项目本地体积（含预计的预处理产物），若可能超过数据盘免费 50 GB，**先提醒用户在实例页面扩容**再上传（扩容按天计费、关机也计费，见第五章）。
- ⭐ **阶段 8 之后补一条收尾**：提醒清掉云端可再生的大文件（预处理中间产物、冗余 checkpoint、压缩包副本），并缩容数据盘或释放实例，否则扩容费会持续扣。
- 阶段 5 提醒一次"**关浏览器 ≠ 关机**"；阶段 7 提醒"**关机而不是释放**"。
- 若用户没给登录指令，就只给带 `<端口>/<地址>` 占位符的版本，并再次说明"要拼完整命令需要那行登录指令，密码不用发"。
