# babeldoc 版面保全翻译守则

> **适用场景**：Agent 在两遍流水线的中间阶段直译 `pending.jsonl` 时，逐条必须遵循本守则。
> 违反守则会导致 babeldoc 回填失败、占位符丢失或版面错乱。

---

## 〇、方法论依据与补充阅读

本守则以四项翻译质量支柱为方法论基础（术语一致性 / 形态冻结 / 数据保真 / 学术文体+回译）。下列 5 个参考文件是本守则的深度依据，**阶段 2 直译时按需查阅**：

| 文件 | 何时读 |
|---|---|
| `references/translation-rules.md` | 想理解"为什么这样翻"——四支柱原理（术语 / 形态冻结 / 数据保真 / 学术文体+回译）的方法论溯源 |
| `references/glossary-template.md` | 译前建术语表、或译后输出 `<terminology>` 一致性清单时 |
| `references/academic-format-cheatsheet.md` | 遇到不熟悉的 LaTeX / 公式 / 引用 / 单位语法，确认哪些必须原样 |
| `references/academic-style-guide.md` | 雕琢学术文风——中↔英句式模板、时态/语态/缩写规范、常见术语参考译法、翻译陷阱与译后质量清单 |
| `references/faq.md` | 用户问"公式能不能翻 / 数据要不要改 / 能不能双语"等高频问题，或自查反模式 |

贯穿本守则的四支柱（底层原则）：
1. **术语一致性引擎**：译前建表、每批注入、全程套用、译后输出清单（见 §四扩展）。
2. **形态冻结**：公式 / 数据 / 引用 / 编号原样（见 §二、§五、§12b）。
3. **数据保真（去幻觉）**：数值逐字、不修正不补充（见 §四-b）。
4. **学术文体 + 回译校验（去 AI 味）**：被动语态、非口语、回译自查（见 §四-c）。

---

## 一、结构规则（最高优先级）

1. **条目数守恒**：输出条目数必须与输入完全一致。不合并、不拆分、不跨条目搬运内容。
2. **每条独立**：一条 `input` 可能只是原始段落被版面切开的一个切片（可能句子不完整、开头小写、结尾没标点）。
   把它当作**独立固定单元**翻译，不要试图补全上下文或与相邻条目合并。
3. **词序可调，语义不变**：条目内部可以调整语序让中文通顺，但不得改变含义，
   也不得把占位符 / 标签 / 代码移出本条目。
4. **全部人类可读内容译为简体中文**。

## 二、禁止改动的内容

5. **标签原样保留**：`<style ...>`、`<b>`、`<i>`、`<code>` 等标签**连同其属性一字不改**，
   只翻译标签**内部**的人类可读文本。`<code>…</code>` 内的代码**不译**。
6. **占位符原样保留**：`{v1}`、`{v23}`、`{name}`、`%s`、`%d`、`[[...]]`、`%%...%%` 等
   **绝不翻译、绝不改动、绝不增删、绝不调整编号**。
   - `{vN}` 是 babeldoc 的**公式/图形占位符**，回填时会被还原成原始公式。丢失即公式丢失。
   - 占位符在句中的位置可随中文语序移动，但**必须仍在同一条目内、且数量一致**。
7. **JSON 键名与结构保持不变**。

## 三、输出格式

8. 每条输出**只给译文本身**，不要解释、不要引号包裹、不要 ```` ```json ```` 代码块、不要前后缀。
9. 中文须通顺、专业；标点除非为通顺需要，否则沿用原文习惯。

## 四、术语一致性引擎

> **这是提升术语准确度最关键的一步，也是 babeldoc-trans 此前相对薄弱的环节。** 通用翻译靠模型概率，学术翻译靠**强制术语表注入**；跨批概念漂移（同一词前后译法不一）是审稿人最忌的问题。

### 译前建表 → 每批注入 → 译后输出（核心质量杠杆）

- **译前扫描（阶段 2 开始前必做）**：先通读 `pending.jsonl` 全部待译条目，提取领域术语、专有名词、缩写、约定译法，形成一份术语表（格式见 `references/glossary-template.md`）。
- **每批注入**：翻译每一批（30–40 条）时，把术语表置于该批上下文顶部**强制套用**，确保同一概念全篇同译。
- **译后输出**：全部译完后，输出一份 `<terminology>` 清单（原文::译文），随成品一并汇报给用户，供人工核对。

10. **术语一致性**：同一术语在全文任何出现处（含标签内部、跨行断开处）必须使用同一译法。
    建议在开译前先扫一遍 `pending.jsonl`，为高频专有名词定一份术语表再逐批翻译。
11. 模型名 / 架构名 / 数据集名 / 评价指标等专有名词**保留英文原文**
    （如 `Transformer`、`ViT`、`nnU-Net`、`Dice`、`BraTS`），必要时用「英文（中文）」形式首次出现时标注一次。

### 四-b、数据保真（去幻觉 · 四支柱 3）

- 所有数值、百分比、`95% CI [a,b]`、统计量、`p<0.05`、样本量——**逐字一致**，不得改动。
- **不"修正"原文明显笔误**（如把 `0.5%` 改成 `5%`），**不"补充"缺失上下文**。
- 若原文疑似错误，保留原值并在译文后以 `（原文如此）` 标注，由用户判断。绝不自行发挥。

### 四-c、学术文体与回译校验（去 AI 味 · 四支柱 4）

- 被动语态优先、非口语化、信达雅；避免"值得注意的是""综上所述""值得一提的是"等 AI 味套话，避免翻译腔（如过度直译的"被给予""进行实验"）。
- 关键句 / 结论句译后做**回译**（翻回源语）或自查，检测语义是否漂移；漂移即重译该句。

## 五、原样返回（不译）

12. 整条内容若属下列情形，**原样返回**：
    - 纯代码或纯标识符（如 `Transformer`、`ViT`、`ReLU`）
    - 图表编号（如 `Fig. 1`、`Table 2`、`Eq. 3`）
    - URL / DOI / arXiv 编号
    - 纯数字、纯符号、纯占位符

> 注：上述大部分情形脚本已在 collect 阶段用白名单自动透传（写入 `auto_filled.json`），
> 不会出现在 `pending.jsonl` 里。若仍出现，按本条处理。

12b. **铁律：图和表整体不翻译，只翻译图注 / 表注。**

  「图表本身」是完整概念——凡是画在图里、排在表格里的文字，全部保持英文原样：

  - **图内**：坐标轴标签（`Dice Score`、`Kernel Size`）、刻度数字、图例文字、
    图内注记、子图编号 `(a)/(b)`、箭头旁的说明
  - **表内**：表头、行标题、列标题、单元格内容、表内单位标注

  **只有「注」要翻译**：图注（`Figure 3: ...`）、表注（`Table 2: ...`）、
  表脚注（`Best results in bold.`）、公式说明。

  原因：图表内文字与矢量图形共用一套坐标系，替换成中文后字宽变化会覆盖曲线、
  撑破单元格、与坐标轴错位；且 axis label / legend 是国际通用记法，译了反而难读。

  脚本已在 babeldoc 选段阶段用**版面标签 + 几何包含**双判据自动剔除图表内段落，
  正常情况下它们不会出现在 `pending.jsonl`。但版面模型偶有漏判（部分论文会把图内
  文字标成 `fallback_line`），**如果你在 `pending.jsonl` 里看到形如坐标轴标签、
  图例、表头、单元格数值的碎片，一律原样返回，不要翻译。**

## 六、参考文献

13. 参考文献条目**默认原样保留英文**（脚本白名单已自动透传）。
    文献标题译成中文会导致无法检索原文，属有害翻译。
    确需翻译时，运行脚本加 `--translate-refs`。

## 七、示例

| 输入 `input` | ✅ 正确输出 | ❌ 错误输出 |
|---|---|---|
| `We propose MedNeXt, a {v1} network.` | `我们提出 MedNeXt，一种 {v1} 网络。` | `我们提出 MedNeXt，一种网络。`（丢占位符） |
| `<style id='2'>Fig. 2.</style> Overview of the architecture.` | `<style id='2'>Fig. 2.</style> 架构总览。` | `<style id='2'>图 2。</style> 架构总览。`（改了标签内编号且标签外内容被吞） |

## 八、标题翻译特别提示

论文标题（`__TITLE__`）会被用作输出文件名，并渲染在中文版 PDF 首页，因此请额外注意：

1. **通顺优先**：标题可以打破原文语序，按中文习惯组织。例如
   `MedNeXt: Transformer-driven Scaling of ConvNets for Medical Image Segmentation`
   不宜逐字硬翻成 `ConvNet 规模化用于医学图像分割`，应译为
   `MedNeXt：面向医学图像分割的 Transformer 驱动 ConvNet 规模化网络`。
2. **专有名词保留英文**：`Transformer`、`ConvNet`、`MedNeXt`、`ViT`、`BERT` 等模型/架构名保留英文；首次出现时可在括号内补充中文，但标题长度有限，通常直接保留英文更稳。
3. **长度 ≤ 40 字**：文件名有长度限制，标题尽量精炼。
4. **主张核实（强制）**：翻译标题前，先回答三问并落定再动笔——① **主语是谁**：原标题的动作由谁发出（人 / 作者 / 读者，还是 AI / 工具 / 现象）；② **动作方向**：是呼吁人去做某事，还是描述某事发生，还是评论某现象；③ **情感/语气烈度**：严肃批评、愤怒控诉、自嘲调侃，还是温和建议。中文标题必须**完全保留主语身份与动作方向，不得替换主语**。反例：原文 `Thoughts on slowing the fuck down`（主语：作者/开发者，呼吁人放慢节奏）被误译为「让 AI Coding 慢下来」——主语从"人"替换为"AI Coding"，与原文核心主张完全相反。标题中每个词都必须服务于正确的主语与方向。

## 九、写回格式

翻译结果按批次**追加**写入 `work/translations.jsonl`，每行一个 JSON 对象。
支持两种写法，可混用：

```jsonl
{"k": "<pending.jsonl 该条的 k 字段>", "output": "<译文>"}
{"input": "<与 pending.jsonl 完全一致的原文>", "output": "<译文>"}
```

**强烈建议用 `k` 形式。** `k` 是原文的 12 位内容哈希，由脚本在 `pending.jsonl`
里给出。用 `k` 就不必逐字重抄原文，从根本上避免「少一个空格 / 吃掉 `{v1}` /
标签属性写错」导致注入未命中——这是本流程最容易翻车的地方。

- 用 `input` 形式时，必须与 `pending.jsonl` 中的字符串**逐字节一致**（含首尾空格、占位符、标签）。
- 标题条目的 `k` 对应特殊键 `__TITLE__`，其译文用作输出 PDF 的文件名，长度建议 ≤ 40 字。
- 追加写入即可，**重复键以最后一次为准**；因此可以分批写、可以重跑补漏。
- 每批建议 **30–50 条**（或累计 ≤ 8000 字符），写盘后再翻下一批，避免中途失败前功尽弃。
- 写完随时用 `--status` 查覆盖率；渲染后看 `[INJECT] 命中/未命中` 确认是否有漏网。
