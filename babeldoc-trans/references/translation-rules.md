# 翻译质量方法论（translation-rules.md）

> 本文件阐述 babeldoc-trans 翻译内核的「四支柱」原则及其依据——为什么这样翻、翻错会怎样。阶段 2 直译 `pending.jsonl` 时，这四支柱贯穿全程，是 `babeldoc_翻译守则.md` 的方法论底座。

> 本文件是 babeldoc-trans 翻译内核的"为什么这样翻"依据。核心方法论提炼自 PDFMathTranslate（MIT）的翻译指令内核，并经认知放大器调研交叉验证（置信度 72%，Seal-L2）。

## 一、PDFMathTranslate 方法论溯源

PDFMathTranslate 能在保留公式排版的同时做双语翻译，其翻译内核依赖三条工程化经验，本 skill 继承并中文化：

1. **上下文连贯（Context Continuity）**
   - 原文：翻译时把前序与后续段落作为上下文注入，避免孤立句导致的语义漂移。
   - 本 skill 落地：长文本分块，每批带 ±5 段上下文（见 SKILL.md 硬规则 6）。
2. **术语表一致（Glossary Consistency）**
   - 原文：建立术语表（term table）并强制套用，防止同一概念不同译法。
   - 本 skill 落地：支柱 1 术语一致性引擎（扫描→注入→输出 `<terminology>` 清单）。
3. **公式保留（Formula Preservation）**
   - 原文：识别 LaTeX/数学公式块，原样保留不翻译，仅翻译自然语言文字。
   - 本 skill 落地：支柱 2 形态冻结（公式/数据/引用编号原样）。

> 注：PDFMathTranslate 的"排版保留"属工程层（PDF 解析/双语对齐）；纯 skill 只做**翻译内核**（文本进文本出），不自动解析/回填 PDF。这与"只做 skill 发挥模型威力"方向一致。

## 二、四支柱原理（认知放大器调研）

### 支柱 1 · 术语一致性引擎（5/5 源共识，最强）
- 通用翻译靠概率，学术翻译靠**强制注入**。审稿人最忌概念漂移。
- 实践：译前扫描提取术语表 → 注入 prompt → 全程套用 → 输出一致性清单。

### 支柱 2 · 形态冻结（结构保留）
- LaTeX 错位会让 PDF 编译失败；数据/引用编号错位会破坏学术严谨。
- 实践：公式、行内数学、上下标、单位、引用、章节/图表编号——原样保留。

### 支柱 3 · 数据保真（去幻觉）
- 所有数值逐字一致，不"修正"不"补充"。
- 实践：数值/百分比/置信区间/统计量/p 值逐字核对；疑似错误保留原值并标「（原文如此）」。

### 支柱 4 · 学术文体 + 回译（去 AI 味）
- 被动语态、非口语、信达雅；避免 AI 味套话与翻译腔。
- 实践：关键句回译校验语义漂移。

## 三、工程手段：长文本分块
- 翻译损耗 = 语义漂移 + 格式坍塌，根因是"上下文丢失率"。
- 实践：每批 20–30 段 + 每批附术语表 + 上下文 ±5 段。

## 四、边界声明（学术伦理）
- 学术翻译供参考，关键术语/数据需人工复核。
- 含未发表/敏感数据注意泄露风险。
- 版权：翻译他人论文仅供个人学习，发布/商用需获授权。
